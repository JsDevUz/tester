# Button and Message Content Blocks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Button content-block type (styled link with color/target options) and a Message content-block type (ordered chat-bubble text lines, sender resolved server-side as the student's curator, or the course's teacher if no curator is assigned) to the lesson editor, matching this app's existing content-block patterns end to end (DB → service → controller → frontend store → editor UI → student render).

**Architecture:** Both block types are rows in the existing `content_blocks` table, discriminated by `type = 'button'` / `type = 'message'`, following the exact pattern already used by `live_class`/`file`/`video` blocks. Button reuses existing columns (`label`) plus four new nullable/defaulted columns. Message needs an ordered one-to-many child table (`message_block_lines`) since a Message block holds multiple text lines. The student-facing read path (`groups.service.ts`'s `getMyCourseDetail`) resolves each message block's sender once per lesson-list fetch (curator if assigned, else the course teacher) and stamps it onto every message block's response — no client-side sender logic.

**Tech Stack:** NestJS + Drizzle (backend), React + TypeScript + Zustand (frontend), matching the LaTeX plan's verification approach (typecheck + build + code-path tracing; no live browser access in this environment, so any purely-visual step is called out explicitly as manual QA).

## Global Constraints

- No "add another button" / "add another message line" control lives inside a modal — this app has no per-block settings modal at all (confirmed by reading `ContentBlockView.tsx`); Button/Message settings render inline in the block's card exactly like every other block type.
- A Message block always keeps at least 1 line; deleting the last line is rejected server-side with a `BadRequestException`.
- The Message block's sender (name + avatar) is never editable per-block and never computed client-side — it is resolved server-side as: the student's group curator if one exists, else `course.adminId` (the teacher). This mirrors the existing fallback rule in `practice-messenger.service.ts:619` (`curator?.schoolMember?.studentId ?? course.adminId`), reimplemented fresh for this read path.
- A Button block with no `buttonUrl` set renders nothing on the student side (same precedent as an unconfigured `live_class` block being skipped for students).
- Both new block types respect the existing `CONTENT_BLOCK_LIMIT = 7` per-lesson cap, exactly like every other block-creation method in `content-blocks.service.ts`.
- All new backend mutations go through the same `assertLessonOwnership` (or an equivalent walk for message-line mutations) ownership check every existing mutation in `content-blocks.service.ts` already uses.
- No test suite exists today for `content-blocks.service.ts`/`controller.ts` (confirmed) — this plan does not introduce one for the new endpoints either, matching the codebase's existing precedent for `live_class`/`file` block creation. Verification is TypeScript compilation, a full build, and manual code-path tracing/QA, matching the LaTeX plan's approach in this same session.

```ts
  private async assertMessageLineOwnership(lineId: string, adminId: string) {
    const line = await db.query.messageBlockLines.findFirst({ where: eq(messageBlockLines.id, lineId) });
    if (!line) throw new NotFoundException('Message line not found');
    const block = await db.query.contentBlocks.findFirst({ where: eq(contentBlocks.id, line.contentBlockId) });
    if (!block) throw new NotFoundException('Message line not found');
    await this.assertLessonOwnership(block.lessonId, adminId);
    return line;
  }

  async addMessageLine(blockId: string, adminId: string) {
    const block = await db.query.contentBlocks.findFirst({ where: eq(contentBlocks.id, blockId) });
    if (!block || block.type !== 'message') throw new NotFoundException('Message block not found');
    await this.assertLessonOwnership(block.lessonId, adminId);
    const existing = await db.query.messageBlockLines.findMany({ where: eq(messageBlockLines.contentBlockId, blockId) });
    const [line] = await db
      .insert(messageBlockLines)
      .values({ contentBlockId: blockId, orderIndex: existing.length, text: '' })
      .returning();
    return line;
  }

  async updateMessageLine(lineId: string, adminId: string, text: string) {
    await this.assertMessageLineOwnership(lineId, adminId);
    const [updated] = await db
      .update(messageBlockLines)
      .set({ text })
      .where(eq(messageBlockLines.id, lineId))
      .returning();
    return updated;
  }

  async removeMessageLine(lineId: string, adminId: string) {
    const line = await this.assertMessageLineOwnership(lineId, adminId);
    const siblingCount = await db.query.messageBlockLines.findMany({
      where: eq(messageBlockLines.contentBlockId, line.contentBlockId),
    });
    if (siblingCount.length <= 1) {
      throw new BadRequestException("Xabar blokida kamida bitta qator bo'lishi kerak");
    }
    await db.delete(messageBlockLines).where(eq(messageBlockLines.id, lineId));
  }

  async reorderMessageLines(blockId: string, adminId: string, lineIds: string[]) {
    const block = await db.query.contentBlocks.findFirst({ where: eq(contentBlocks.id, blockId) });
    if (!block || block.type !== 'message') throw new NotFoundException('Message block not found');
    await this.assertLessonOwnership(block.lessonId, adminId);
    const existing = await db.query.messageBlockLines.findMany({
      where: and(eq(messageBlockLines.contentBlockId, blockId), inArray(messageBlockLines.id, lineIds)),
    });
    if (existing.length !== lineIds.length) {
      throw new BadRequestException("lineIds must match the block's existing lines");
    }
    for (let i = 0; i < lineIds.length; i++) {
      await db.update(messageBlockLines).set({ orderIndex: i }).where(eq(messageBlockLines.id, lineIds[i]));
    }
  }
```
